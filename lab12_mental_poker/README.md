# Лабораторная работа №12 — «Ментальный покер» (Техасский холдем)

Реализация криптографического протокола **SRA (Shamir–Rivest–Adleman, 1978)** для игры
в Техасский холдем без доверенного дилера — с графическим веб-интерфейсом,
произвольным числом игроков (2–6) и выбором колоды (36 или 52 карты).

Каждому игроку раздаётся по 2 закрытые карты, на стол выкладываются 5 общих карт
(флоп 3, тёрн 1, ривер 1). Победитель определяется публичным алгоритмом
оценки 7-карточной руки (лучшая из C(7,5) = 21 пятёрок).

## Быстрый запуск

Требуется только **Python 3.8+** (стандартная библиотека, без pip-зависимостей):

```bash
python3 server.py            # http://127.0.0.1:8012
python3 server.py --port 9000
```

Открыть в браузере: <http://127.0.0.1:8012>

## Как пользоваться

1. **«Новая игра»** — выбрать число игроков, имена, размер колоды (52/36) и разрядность
   простого `p` (512 бит — рекомендуется; 256 бит — для быстрой демонстрации).
2. Нажать **«Сгенерировать параметры и ключи»**: генерируется безопасное простое
   `p = 2q + 1`, ключи `(eᵢ, dᵢ)` каждого игрока, колода по очереди зашифровывается
   ключами всех игроков и перемешивается **каждым** игроком.
3. **«Раздать по 2 карты»** — карты вскрываются совместным применением `dᵢ` всех игроков
   (закрытыми показываются только владельцу; клиент получает лишь факт раздачи).
4. **Флоп → Тёрн → Ривер** — выкладываются общие карты (каждая — совместным вскрытием).
5. **«Вскрытие»** — открываются закрытые карты, определяется победитель (или делится банк при ничьей).
6. **«🛡 Защищённость и честность»** — полное обоснование схемы (см. также ниже).

## Протокол кратко

```
p = 2q + 1 — безопасное простое           (все вычисления в Z*_p)
кодировка карты:  m = h² mod p,  h = SHA-256("mental-poker|колода|номер|salt") mod (p−3) + 2
игрок i:          eᵢ ← случайное нечётное, НОД(eᵢ, p−1) = 1;   dᵢ = eᵢ⁻¹ mod (p−1)
шифрование:       c ← m^(e₁·e₂·…·eₙ) mod p   (каждый игрок возводит в свою степень)
тасовка:          каждый игрок случайно переставляет зашифрованную колоду (Фишер–Йетс)
вскрытие карты:   последовательно c ← c^dᵢ mod p для всех i (порядок не важен)
```

## Обоснование защищённости и честности

### Честность раздачи
* После шифрования колоду перемешивает **каждый** игрок независимо своей случайностью.
  Итоговая перестановка — композиция перестановок всех участников.
* Пока **хотя бы один** игрок тасует честно, никто — ни один другой игрок, ни даже
  сговорившиеся все остальные — не может знать или вычислить итоговый порядок.
* Выбор позиции «нужной карты» невозможен: карта неотличима от других шифртекстов.

### Конфиденциальность (скрытость карт)
* Вскрыть карту можно только совместным применением `d₁…dₙ`, т.е. **всеми** игроками
  (порог n из n). Сговор n−1 игроков бессилен без оставшегося.
* Показатель степени складывается в показатель: `m^(e₁e₂…eₙ) mod p`;
  обратная операция требует знания всех `dᵢ`.
* Коммутативность возведения в степень по одному модулю ⇒ порядок расшифровки
  произвольный, ни один игрок не получает преимущества по ходу.

### Стойкость к известным атакам на SRA
* **Атака по символу Лежандра** (`(mᵉ/p) = (m/p)` при нечётном `e`): устранена тем, что
  кодировки карт являются квадратичными вычетами (`m = h² mod p`) — все шифртексты тоже
  вычеты, признак ничего не различает.
* **Перебор/словари**: кодировки — 256-битные значения, связанные с номером карты через
  SHA-256; восстановление соответствия «шифртекст ↔ карта» требует решения задачи
  RSA (возведения в степень по модулю составного… то есть вычисления дискретного/
  экспоненциального обращения) — при 512+ битах невозможно.
* **Малые `e`**: `eᵢ` берутся взаимно простыми с `p−1`, `x ↦ x^eᵢ` — перестановка
  мультипликативной группы; коллизий кодировок быть не может (проверяется при генерации).
* Знание открытого текста не помогает: схема асимметрична по секрету `dᵢ`, 
  открытый ключ `eᵢ` безопасно показывать (в интерфейсе есть переключатель
  «показать секреты dᵢ» — только для демонстрации на защите).

### Проверяемость и честность результата
* Вскрытие любой карты воспроизводимо: любой игрок может заново применить
  свои `dᵢ` к зафиксированным шифртекстам и убедиться в результате.
* Оценка руки — детерминированный публичный алгоритм (`holdem.evaluate7`),
  перебирающий все 21 пятёрок; обмануть его нельзя.

### Границы схемы (что важно сказать на защите)
* **Отказ в обслуживании**: игрок может не отдать `dᵢ` и заблокировать вскрытие
  (свойство любой схемы n-из-n). Защита от этого требует пороговых схем / реконструкции
  секрета — за рамками лабораторной.
* **Детерминированность** шифртекстов позволяет отслеживать перемещения карты
  (не узнавая её значения). Промышленное решение — рандомизация (Эль-Гамаль)
  и доказательства перемешивания с нулевым разглашением.
* Сговор **всех** игроков = отсутствие шифрования (вырождение, атакой не является).
* Торги/банк не реализованы сознательно: задача работы — протокол раздачи и вскрытия.
