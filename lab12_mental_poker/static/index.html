Журнал протокола

    Обоснование защищённости и честности схемы

    1. Что именно защищает схема

    • Конфиденциальность карт. Ни один игрок (и не сговорившиеся вплоть до n−1 игроков) не может узнать чужие закрытые карты до вскрытия.
    • Честность раздачи. Никто не может подтасовать порядок колоды или «подсмотреть» нужную карту из колоды.
    • Проверяемость. Все шаги фиксируются в журнале протокола; итог вскрытия перепроверяем публичным вычислением.

    2. Почему карту нельзя вскрыть в одиночку

    Каждая карта кодируется числом m ∈ (2, p−1), где p — безопасное простое (p = 2q + 1). Игрок i выбирает секретные eᵢ (взаимно простое с p−1) и dᵢ = eᵢ−1 mod (p−1). Шифрование — c = me mod p. Показатели перемножаются:

    c = m^(e₁·e₂·…·eₙ) mod p

    Вскрыть карту можно, только последовательно применив d₁, d₂, …, dₙ — то есть всем игрокам вместе (порог n из n). Сговор n−1 игроков не может прочитать карту без оставшегося. Расшифровка коммутативна: порядок применения dᵢ не важен, поэтому никто не получает преимущества от порядка хода.

    3. Почему тасовка честная

    После шифрования каждый игрок независимо применяет к колоде свой случайный Фишер–Йетс (с энтропией ОС). Итоговый порядок — композиция перестановок всех игроков. Пока хотя бы один игрок перемешивает честно, никто другой не знает и не может предсказать итоговый порядок: злоумышленник не может ни отследить конкретную карту, ни выбрать её позицию.

    4. Почему шифртекст не выдаёт карту

    • Раскрытие c = mE mod p без знания факторизации p−1 эквивалентно взлому RSA — при 512+ битах практически невозможно.
    • Атака по символу Лежандра (шифр сохраняет вычетность: (me/p) = (m/p)) устранена: кодировки карт берутся как квадраты h² mod p, поэтому все открытые тексты — вычеты, и все шифртексты — вычеты. Признак «лександров == 1» не различает карты вообще.
    • Кодировки — 256-битные числа из SHA-256, пространство кодов огромно; угадать карту перебором нельзя даже в принципе (их всего 52, но проверить соответствие кандидата шифртексту можно лишь полным вычислением, которое и есть задача RSA).
    • eᵢ взаимно просты с p−1 ⇒ x ↦ xeᵢ mod p — перестановка Z*p; ни одна карта не теряется и не склеивается с другой.

    5. Границы и допущения

    • Схема SRA даёт конфиденциальность и честный порядок, но не мешает отказу в обслуживании: любой игрок может заблокировать вскрытие, не отдав свой dᵢ. (То же делает любой протокол n-of-n.)
    • Шифрование детерминировано: одинаковые входы дают одинаковый шифртекст, поэтому шифртексты позиций можно перемещательно отслеживать (не узнавая их значения). Для скрытия даже этого факта в промышленных схемах применяют рандомизированное шифрование (Эль-Гамаль) и доказательства с нулевым разглашением перетасовки.
    • Вскрытие происходит только по совместному действию, поэтому открыть «лишнюю» карту нельзя — протокол всегда вскрывает ровно нужные позиции.
    • Сговор всех игроков эквивалентен отсутствию шифрования — но это не атака, а вырожденный случай: участники и есть владельцы секретов.
    • Беттинг (торги, банк) в работу не входит: цель — показать криптографический протокол раздачи и вскрытия; оценка победителя считается публичным алгоритмом evaluate7 (перебор 21 пятёрки из семи карт).

    6. Что показать преподавателю на защите

    1. Кнопка «Новая игра»: видно генерацию p, q = (p−1)/2 и ключей eᵢ/dᵢ каждого игрока.
    2. Журнал: перемешивание выполняет КАЖДЫЙ игрок — честность не зависит от одного участника.
    3. Флоп/тёрн/ривер/вскрытие: каждая карта вскрывается последовательностью из n шагов «применить dᵢ игрока i» — видны промежуточные числа.
    4. Ни одна карта не показывается до вскрытия; закрытые карты соперников недоступны клиенту (сервер отдаёт только факт «2 карты розданы»).
    5. Победитель определяется детерминированно и проверяемо (все C(7,5)=21 пятёрок).
